### 2.3 数据流

| Tab | 功能 | 读取方式 | 写入方式 | 核心算法 |
|-----|------|---------|---------|---------|
| Tab1 Excel处理器 | 多源列 -> 模板列映射合并 | SAX 流式（.xlsx）/ POI（.xls） | SXSSFWorkbook | HeaderMapping 列映射 + 多源合并 |
| Tab2 建立映射 | 从关系表提取映射对 | POI 全量 | 内存 Map | 两列读取 -> Map<String,String> |
| Tab3 应用映射 | 按映射关系填充目标表 | SAX 流式（.xlsx）/ POI（.xls） | SXSSFWorkbook | 反向映射 + 逐行查找填充 |
| Tab4 跨表填充 | 按主键匹配填值 | POI 全量 | SXSSFWorkbook | HashMap 索引 + 键匹配 |
| Tab5 重复列合并 | 按主键去重合并行 | POI 全量 | SXSSFWorkbook | LinkedHashMap 分组 + LinkedHashSet 去重 |

### 2.4 设计模式

- **SwingWorker**：所有文件 I/O 操作在后台线程执行，避免阻塞 EDT
- **SAX 事件流**：XLSX 文件解析使用 `XSSFReader` + `SharedStringsTable`，避免 OOM
- **SXSSFWorkbook 流式写入**：100 行内存窗口 + 1000 行批量刷新，所有 5 个 Tab 统一使用
- **ProgressDialog 包装类**：类型安全的进度对话框（dialog/label/progressBar 字段）
- **AppContext 共享上下文**：持有 mainFrame/logArea/statusLabel，通过构造函数注入各 Panel

## 四、TOP 5 优先优化点（已全部完成）

### 优化 1：CrossSheetFiller / DuplicateColumnMerger 输出改用 SXSSFWorkbook ✅

**现状（优化前）**

| 方法 | 输出工作簿 | 内存模型 |
|------|-----------|---------|
| `CrossSheetFiller.fill()` | `new XSSFWorkbook()` | O(n) — 全量加载 |
| `DuplicateColumnMerger.mergeByKeyColumn()` | `SXSSFWorkbook(100)` | O(100) — 流式 ✅ |
| `DuplicateColumnMerger.mergeByCustomerIdWithProgress()` | `new XSSFWorkbook()` | O(n) — 全量加载 |

**已完成的修改：**
- `CrossSheetFiller.fill()`：输出改用 `new SXSSFWorkbook(100)`，写出后调用 `dispose()`
- `DuplicateColumnMerger.mergeByCustomerIdWithProgress()`：同理改用 SXSSFWorkbook

**收益：** 所有 Tab 的 Excel 写入统一使用 SXSSFWorkbook，大文件不再 OOM。

---

### 优化 2：applyMapping() 改用 SAX 流式读取 + SXSSFWorkbook 写入 ✅

**现状（优化前）：** Tab3 使用 `XSSFWorkbook` 读取源文件和写入输出文件，全量加载到内存。

**已完成的修改：**
- 读取：XLSX 文件复用 SAX 流式解析（HeaderHandler + SheetDataHandler）
- 写入：改用 `SXSSFWorkbook(100)` + 批量刷新
- XLS 文件仍使用 POI 全量读取（.xls 格式不支持 SAX）

**收益：** Tab3 处理大 XLSX 文件时内存从 O(n) 降到 O(100)。

---

### 优化 3：消除三个类中的重复代码 ✅
